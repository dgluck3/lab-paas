# Шпаргалка: лабораторная по PaaS (Railway + Git + VS Code)

## 1. Ответы на контрольные вопросы

**1. Почему гибкая разработка (Agile) становится популярнее?**
- Работа идёт короткими итерациями, после каждой заказчик видит результат и может сразу скорректировать требования.
- Меньше риск сделать не то, что нужно: ошибки находят рано, а не в конце проекта, как в каскадной модели.
- Новую версию нужно часто выкатывать, а облачные платформы (PaaS) делают это автоматически.
- Минус: из-за нечётких формулировок результата сложно заранее оценить трудозатраты и стоимость.

**2. Преимущества PaaS перед IaaS**
- В IaaS вы получаете «голое железо» (виртуальную машину): сами ставите ОС, настраиваете сеть, обновления, веб-сервер, масштабирование.
- В PaaS платформа берёт всё это на себя: вы отдаёте только код, а сборка, запуск, домен, HTTPS, логи и масштабирование уже готовы.
- Результат: быстрее старт, меньше администрирования, удобно деплоить каждую итерацию.
- Цена за удобство: меньше контроля над окружением и привязка к платформе.

**3. Зачем нужны add, commit, push**
- `git add` — выбрать изменения и поместить в индекс (подготовить к коммиту).
- `git commit` — сохранить снимок изменений в локальной истории с комментарием.
- `git push` — отправить коммиты в удалённый репозиторий (GitHub). Именно push запускает автодеплой на Railway.

**4. Преимущества облачной платформы (Railway/Heroku) перед локальным окружением**
- Публичный адрес и HTTPS из коробки: приложение доступно всем, а не только на вашем компьютере.
- Деплой одним `git push`, не нужно настраивать свой сервер и инфраструктуру.
- Одинаковое окружение для всех, нет проблемы «у меня работает».
- Логи, метрики, переменные окружения, откат к прошлой версии, масштабирование.
- Работает без включённого вашего компьютера.

## 2. Главный рабочий цикл (запомнить)

В терминале VS Code (`` Ctrl+` ``), в папке проекта:

```bash
source venv/bin/activate        # включить виртуальное окружение (если не включено)
python app.py                   # проверить локально: http://localhost:5000
```

Если всё работает, останавливаем (`Ctrl+C`) и отправляем:

```bash
git status                      # что изменилось
git add .                       # добавить все изменения
git commit -m "Что изменил"     # сохранить снимок
git push                        # отправить на GitHub -> Railway сам задеплоит
```

Дальше открываем Railway → сервис → **Deployments**: новая запись пройдёт Building → Deploying → ACTIVE (около минуты). Потом обновите страницу сайта (⌘R или ⌘⇧R для жёсткого обновления).

**То же самое мышкой в VS Code:** значок Source Control слева (⌃⇧G) → «+» у файлов → сообщение → Commit → Sync Changes.

## 3. Если добавили новую библиотеку

```bash
pip install название
pip freeze > requirements.txt   # обязательно! иначе Railway её не поставит
git add . && git commit -m "Add library" && git push
```

## 4. Railway CLI (уже привязан)

```bash
railway whoami                  # под каким аккаунтом вошли
railway status                  # к какому проекту/сервису привязана папка
railway logs                    # логи работающего приложения
railway open                    # открыть сайт в браузере
railway variables               # показать переменные окружения
railway variables --set "GREETING=Привет, мир"   # задать переменную
railway up                      # залить код напрямую, минуя GitHub
railway run python app.py       # запустить локально с переменными из Railway
railway --help                  # все команды (версии CLI отличаются)
```

Важно: **`git push` и `railway up` — два разных способа деплоя.** Для лабы используйте `git push` (так задеплоен проект из GitHub). `railway up` загружает папку как есть, даже с незакоммиченными правками, и такой деплой не попадёт в историю Git.

### Переменные окружения (демонстрация для пункта 5 лабы)
1. Railway → сервис → **Variables** → New Variable: `GREETING` = `Привет из Railway`.
2. Railway сам перезапустит приложение, и на сайте изменится строка под заголовком (код менять не нужно).
3. Код читает её так: `os.environ.get("GREETING", "значение по умолчанию")`.

## 5. Git: полезные команды

```bash
git status                      # состояние: что изменено, что в индексе
git diff                        # что именно изменилось в файлах
git log --oneline               # короткая история коммитов
git branch                      # список веток
git checkout -b feature         # создать ветку feature и перейти в неё
git checkout main               # вернуться в main
git merge feature               # влить ветку feature в текущую
git restore app.py              # отменить незакоммиченные правки в файле
git revert HEAD                 # новый коммит, отменяющий последний (безопасно)
git remote -v                   # куда уходит push
```

Осторожно: `git reset --hard` стирает несохранённые изменения безвозвратно.

## 6. Откат версии

**Способ 1 (быстрый, в интерфейсе):** Railway → Deployments → ⋮ у нужного старого деплоя → Redeploy/Rollback.

**Способ 2 (правильный по Git):**
```bash
git revert HEAD
git push
```

## 7. Если что-то сломалось

| Симптом | Что проверить |
|---|---|
| Деплой Failed | Deployments → View logs: ошибка сборки, чаще нет пакета в `requirements.txt` |
| Сайт 502 / «Application failed to respond» | `Procfile` должен содержать `web: gunicorn app:app --bind 0.0.0.0:$PORT`; в логах ищите traceback |
| После push ничего не изменилось | Сделали ли `git commit`? `git log --oneline`, `git status`; затем жёсткое обновление страницы ⌘⇧R |
| `git push` просит пароль / отказ | Используйте `gh auth login` (GitHub CLI) вместо пароля |
| `ModuleNotFoundError` локально | Не включено окружение: `source venv/bin/activate` |
| Порт 5000 занят на Mac | На macOS порт 5000 может занимать AirPlay. Запустите `PORT=5001 python app.py` и откройте `localhost:5001` |
| В `git status` виден `venv/` | В `.gitignore` должны быть строки `venv/`, `__pycache__/`, `.env` |

## 8. Что показать в отчёте (скриншоты)

1. Локальный запуск (`localhost:5000`).
2. Репозиторий на GitHub с коммитами.
3. Railway: ACTIVE / Deployment successful + домен.
4. Сайт до и после изменения (Version 1 → новая версия).
5. История деплоев (несколько записей).
6. Переменная окружения в Railway и её эффект на сайте.
7. Вывод `git log --oneline` в терминале.
